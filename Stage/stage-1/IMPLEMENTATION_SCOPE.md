# LUNA — Stage 1 Implementation Scope

## IN SCOPE
- Existing LUNA architecture inspection
- Strategic Orchestrator abstraction
- Execution Request/Response contracts
- Engine-agnostic Execution Interface
- Jarvis Adapter boundary/skeleton
- Tests
- Current architecture documentation
- Jarvis GitHub source reconnaissance
- Source-tree mapping
- Component classification
- License/dependency review
- Execution-flow tracing

## OUT OF SCOPE
- Final Context Projection architecture
- Final Shared State model
- Final Memory architecture
- Learning/memory promotion
- Final MCP ownership architecture
- Final Model Routing architecture
- Scheduler/automation architecture
- Voice architecture
- Mobile UI architecture
- Full Jarvis merge
- Replacing DeepSeek
- Backend rewrite
- Speculative multi-agent architecture

## Integration rule

Discover → Understand → Map → Compare → Recommend → Approve → Integrate.

## Stop conditions

Stop and report if:
- a Stage 1 decision conflicts with the codebase
- Jarvis source materially contradicts documentation
- license terms create uncertainty
- integration changes ownership boundaries
- implementation requires a future-stage decision
- a rewrite appears necessary

Do not silently resolve architectural conflicts.
